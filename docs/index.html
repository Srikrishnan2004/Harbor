Store, credential, and switch
MCP servers everywhere.

Harbor is a local gateway + desktop app for your Model Context Protocol servers. Define a server once, give it as many credential sets as you need, bundle them into profiles, and apply a profile to any project across Claude Code, Codex, Gemini CLI & Antigravity — in one keystroke, without ever touching a config file again.

~/code/my-app
# one server, many identities
$ harbor add supabase --id supabase-prod --production
$ harbor add supabase --id supabase-staging

# bundle into a profile, bind it to a project
$ harbor profile create app-dev
$ harbor profile add app-dev supabase-staging github-work
$ harbor bind ~/code/my-app app-dev

# switch live — no client restart
$ harbor profile use app-prod-debug

The problem

MCP config is fragmented and manual.

Every client stores servers its own way, assumes a single identity per server, and re-does auth from scratch.

Config lives in N places~/.claude.json, .mcp.json, ~/.codex/config.toml, ~/.gemini/settings.json — each with its own schema.
One server, one identityProd, staging, and a client's instance mean juggling env vars or duplicated blocks — and hoping you don't hit prod by mistake.
Auth is repeated everywhereOAuth flows and tokens get redone per client, and tokens end up in plaintext JSON on disk.
Switching is manual/mcp, claude mcp add …, re-auth, restart the client. Every single time.
What Harbor does

Instances, profiles, one gateway.

Harbor is a gateway, not a config-file editor. Each client is pointed at Harbor once; Harbor decides what's behind the door.

📚

Server library

Every MCP server you've configured, in one catalog with search, tags, and health status.

🎭

Multiple instances

The same server type with different credentials and scopes — supabase-prod supabase-staging — as first-class, visually distinct entries.

🗂️

Profiles

Named bundles of instances. Apply one to a project or client in a single action.

🔀

Live switching

Switch profiles and the tool set changes instantly — no config rewriting, no client restart.

🔐

Credential vault

OS keychain–backed storage. Auth once, reuse everywhere. Tokens never sit in a JSON blob.

🔗

Cross-client sync

Claude Code, Codex, Gemini CLI, Antigravity — all fed from one source of truth.

🔑

OAuth flows

Full PKCE authorization for remote servers; tokens stored in the vault and refreshed silently.

🛡️

Tool policy & safety

Read-only instances, per-tool allow/deny, confirm-write gates, and filesystem scoping — enforced at the gateway.

📊

Usage analytics

Per-instance calls, error rate, bytes, and latency — the full audit log of every upstream tool call.

📁

Folder awareness

Scan a directory tree to see which projects declare which servers, and where they conflict — then reconcile in one click.

🧩

Registry install

Search the MCP registry and install a server into your library, credentials and all.

👥

Team manifests

Ship a references-only harbor.yaml; a teammate runs harbor sync and brings their own credentials.

Architecture

A gateway, not a config editor.

Each client talks to Harbor once. Behind it, the union of the active profile's instances — namespaced, credential-injected, safety-filtered, and audited.

Get started

Point clients at Harbor once.

After setup, every change happens in Harbor — no client config is ever touched again.

  1. Install

    Clone the repo and install dependencies with pnpm.

  2. Wire up your clients

    harbor setup --all adds a single gateway entry to each detected client.

  3. Add & credential a server

    harbor add supabase … then harbor auth — secrets go straight to the OS keychain.

  4. Bundle & switch

    Group instances into a profile and harbor profile use — live in every client.

# clone & install
git clone https://github.com/Srikrishnan2004/Harbor
cd Harbor && pnpm install

# connect every detected client (once, ever)
./bin/harbor setup --all

# add a server, store its secret in the keychain
./bin/harbor add supabase --id supabase-staging \
  --label "Supabase (staging)" --color yellow
./bin/harbor auth supabase-staging

# bundle into a profile and activate it live
./bin/harbor profile create app-dev
./bin/harbor profile add app-dev supabase-staging
./bin/harbor profile use app-dev

# optional: the desktop control panel
pnpm build:ui && ./bin/harbor daemon   # http://127.0.0.1:4747
